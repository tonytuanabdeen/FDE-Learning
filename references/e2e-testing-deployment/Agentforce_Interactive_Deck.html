Agents aren't Apex

Ask the same question five times and compare two kinds of test.

Apex test

Fixed input, fixed output

Agent test

Free-form input, varied wording

[0:02-0:03] Click "Ask 5 times". The Apex column always matches. The agent column changes wording each time, so an exact-match check fails even when the answer is right, while a key-fact check passes. This is why agent tests check topic, action and key facts, and why we repeat tests.

  • Can I run my own CLI test job as a pipeline step?
  • Does a failing agent test block promotion?
  • What is the audit trail and rollback story?

[0:54-0:58] Change the three selectors and watch the ranking move. Message: no tool wins everywhere. Code-first teams do well with CLI plus CI. Mixed teams gain from a UI. Regulated enterprises need audit and approvals. Verify each vendor's current agent-metadata support before committing; this area moves quickly.

  


  
  

    
The whole flow, end to end

    
Click a step to see what happens and which tool does it.

    

    

    
[0:56-0:58] Recap. A change starts in Builder or the IDE. You preview, then run batch and conversation suites. A pull request triggers the automated tests, which gate the merge. Only a green run deploys. After release, nightly runs keep watching, and every production surprise becomes a new test case.

  


  
  

    

      
Takeaways
and Q&A

      

        
Test at four levels
Manual, batch, automated, multi-turn.

        
Treat the agent as metadata
Version it, review it, deploy it with its dependencies.

        
Let the pipeline say no
A failing agent test blocks the release.

      

      
Homework: build a five-row suite for a sample agent, retrieve it into VS Code and change one line, then deploy to your sandbox and run the tests.
