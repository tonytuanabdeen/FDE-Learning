What the agent can do

Two reasoning paths, one assistant

The agent interprets each message, decides whether it needs structured data or unstructured knowledge, and routes itself to the right tool.

🔎

Structured lookups

“Where is my order ORD-1001?” → the agent calls the Order tool, which runs a validated SQL query against PostgreSQL and returns live status.

📚

Policy retrieval (RAG)

“What is the cancellation policy?” → hybrid search over Qdrant retrieves the right policy chunk and the agent answers, grounded in source documents.

⚙️

Action with approval

“Can I cancel order ORD-1001?” → the agent combines order state and policy, then routes sensitive actions through human-in-the-loop review.

Where it goes next

Roadmap

A phased path from the working prototype to a governed, multi-domain assistant.

Phase 1 · Now

Working prototype

  • Order status + policy RAG live
  • LangGraph orchestration, 3 scenarios
  • React UI, end-to-end locally
  • Core guardrails wired in
Phase 2 · Next

Harden & expand

  • Cancellations & returns as real actions
  • Eval suite + regression tests
  • Observability: traces & audit logs
  • Auth, rate limits, PII masking at scale
Phase 3 · Scale

Multi-domain assistant

  • New tool domains (billing, logistics)
  • Multi-channel: web, email, chat
  • Cloud deploy, CI/CD, autoscaling
  • Continuous eval & model routing
